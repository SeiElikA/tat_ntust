## 0. 三十秒摘要

- **產品**：TAT 是臺灣科技大學的校務 App（`club.ntust.tat`），把學校的單一登入、
  課表、成績、Moodle、行事曆與校內資訊系統包成一支 App。Flutter，Android / iOS
  雙平台，只有手機版面。
- **這次的範圍**：整支 App 的介面重新設計，**視覺與資訊架構都可以動**。
- **平台立場**：**中立**。不要做成一眼認得出的 Material 3，也不要做成一眼認得出的
  iOS。要一套自己的、放在兩個平台上都不突兀的設計語言。
- **品牌**：TAT 自己的主色。**不要**帶入臺科大的校徽、校色或任何學校識別。
- **最重要的一句話**：這支 App 的資料**幾乎每一筆都可能失敗、可能是過期快取、
  可能需要重新登入**。只畫了「資料正常」那一種樣貌的設計不能用——見 §5.1。

## 1. 使用者與使用情境

### 1.1 誰在用

臺科大在學學生。全部是手機使用（沒有平板或桌面版）。多數人一天開 App 3～10 次，
每次停留 10～60 秒。使用高峰是每天 08:00–09:00、每節下課的 10 分鐘、以及期中期末
與選課週。

網路環境不穩定是常態：校內 Wi-Fi 漫遊、地下室教室、通勤中的行動網路。**離線可用
是需求不是加分項**。

### 1.2 六個真實情境（設計要優先服務這些）

| # | 情境 | 頻率 | 現在要做幾件事 |
|---|---|---|---|
| 1 | 「下一堂課在哪間教室」 | 每天數次 | 開 App → 課表 → 自己找出今天是星期幾那一欄 → 點課 → **對話框才顯示教室** |
| 2 | 「有什麼作業快到期」 | 每天 | 底部第 3 個分頁 → 往下捲過整個月曆 → 底部才是待辦 |
| 3 | 「老師剛剛公告了什麼」 | 每週數次 | 課表分頁右上角鈴鐺 →「公告與通知」 |
| 4 | 「這學期成績出來了嗎」 | 期末密集 | 底部第 4 個分頁 → 等一次完整抓取 |
| 5 | 「我要進某個校內系統辦事」 | 每月數次 | 底部第 2 個分頁 → 在 2 欄純文字方塊裡找 → 開 WebView |
| 6 | 「下載老師上傳的講義」 | 每週 | 課表 → 點課 → 對話框「課程資料」→ 檔案分頁 → 可能還要進子資料夾 |

情境 1、2、3 是這支 App 的核心價值，但**現在全部藏在第二層以後**。這是這次翻新
要解決的第一號問題。

## 2. 已定案的設計方向（不需要再提案）

### 2.1 平台立場：雙平台中立

一套設計，在 Android 與 iOS 上都自然。**具體是**：

- **避免** M3 的標誌性語彙：導覽列的藥丸型 indicator、tonal button 的三層色階、
  M3 特有的 FAB 尺寸階梯、`surfaceContainerHighest` 那組容易讓人認出來的灰階。
- **避免** iOS 的標誌性語彙：large title 摺疊、半透明模糊 tab bar、iOS 風格的
  分組表格（inset grouped list）、iOS switch 的綠色。
- **要有**自己的一套：安靜、內容優先、克制的圓角與陰影、一個重音色。
- **平台差異只保留在「肌肉記憶」層**，不在視覺層：轉場方向、返回手勢、觸覺回饋、
  底部選單 vs 對話框的取捨、捲動回彈。這些工程端已經有 `AdaptiveButton`、
  `Switch.adaptive`、`AlertDialog.adaptive` 的既有做法，設計端只要標注「這一顆
  依平台切換」即可，不必畫兩套。

### 2.2 品牌：TAT 自有主色

- 定一組 TAT 自己的主色（含亮/暗兩套的完整色階）。不要臺科大識別。
- 現況是 seed color = `Colors.blue`，並且支援 Android 的 Material You 動態取色
  （`dynamic_color` 套件，`lib/src/config/app_themes.dart`）。
- **本次方向**：品牌色是預設。動態取色降級成設定裡的可選項——所以 token 系統要
  設計成「換掉 seed 就能整套重算」，不要出現寫死的十六進位色散落在元件裡。

### 2.3 範圍：視覺 + 資訊架構

可以重排底部分頁、可以合併頁面、可以新增頁面。**不可以**砍掉既有功能——現有的
每一個資料來源都有人在用，見 §5.6。

## 4. 要解的題目

以下每一條都是實際存在的問題，附了現況檔案。**分級**：P0 = 這次一定要解；
P1 = 應該解；P2 = 有餘力再解。

### A. 導航與資訊架構

**A1（P0）核心資訊全部在第二層以後。**
「下一堂課在哪」要點 4 下、「什麼作業快到期」要捲過整個月曆、「有沒有新公告」
只有課表分頁的鈴鐺看得到。§1.2 的情境 1–3 是這支 App 每天被打開的理由，卻沒有
任何一個能在開 App 的第一眼被回答。
→ **方向**：需要一個「今日 / 首頁」層級的東西。它是不是一個新分頁、還是課表頁
上方的一段、還是把課表頁整個改成「今日視角 + 週視角切換」，由設計端決定。

**A2（P0）「課程資料」與「課程詳情」是兩個不同的頁，名字幾乎一樣。**
兩者都從同一個對話框進入，並列兩顆按鈕。
- 「課程資料」= Moodle 的東西：檔案、公告、Moodle 成績、作業。
- 「課程詳情」= 學校課程查詢 API 的東西：學分、時間、教室、大綱、修課學生。
使用者無法從名字判斷該點哪一個。
→ **方向**：合併成單一「課程」頁。資料來源不同是工程細節，不該外露成兩個頁面。
合併後分頁數會變多（最多 6 個），需要處理分頁列的擁擠。

**A3（P0）沒有「我的課程」清單。**
進入任何 Moodle 課程內容的主要路徑是「課表 → 點對的格子 → 對話框 → 課程資料」。
課表沒載入成功、或那門課這個時段沒有格子（例如只有實習時段、或課表抓取失敗）
就進不去。
工作區裡正在做的「Moodle 目前成績」頁（`pages/score/moodle_course_grades_page.dart`，
從成績分頁右上角進入）意外成了第二條路——它列出這學期每一門課，點一列會開那門課
的課程資料頁。但**那是一個成績頁，不是課程清單**，藏在成績分頁的第二層，而且只有
這學期。
→ **方向**：需要一份名副其實、第一層就到得了的課程清單。（工程端已經在呼叫
`core_enrol_get_users_courses`，資料是現成的。）

**A4（P1）「公告與通知」只有一個入口，而且在課表分頁的 AppBar 上。**
未讀紅點同理——切到其他四個分頁就看不到自己有沒有未讀。

**A5（P1）「其它」分頁的資訊密度極低。**
一張個人資料卡 + 6 個項目（設定、修改密碼、登出、意見回饋、關於），佔掉五分之一
的一級導航。

**A6（P1）「資訊系統」是一個入口網站的功能樹，跟其他四個「內容型」分頁不同層級。**
它底下每一個項目都只是開一個 WebView，本質是一份連結目錄。

**A7（P2）行事曆分頁把兩種完全不同的東西疊在一起。**
上半是學校教務處的行事曆（`.ics`，純文字字串，沒有時間、沒有分類），下半是
Moodle 的個人待辦（有截止時間、有課程歸屬、可點開）。兩者的個人相關度差距極大，
但視覺上沒有區隔。

### B. 狀態、載入與錯誤

**B1（P0）錯誤畫面有三套、載入畫面有四套、提示有兩套。**

| 種類 | 實作 | 用在哪 |
|---|---|---|
| 錯誤 | `ErrorPage`（整頁，圖示 + 一行字 + 可能有登入鈕） | 課表、成績、資訊系統、課程資料 |
| 錯誤 | `InlineErrorView`（區塊，有就地重試鈕） | 行事曆待辦、公告與通知、作業詳情 |
| 錯誤 | `ErrorDialog`（`awesome_dialog` 的彈窗） | `run()` 問「要不要重試」 |
| 載入 | `LoadingPage`（置中一顆轉圈） | 大部分頁面 |
| 載入 | shimmer 骨架 | **只有**個人資料一處 |
| 載入 | `bot_toast` 全螢幕遮罩 + 進度框 | 有 `progressMessage` 的請求 |
| 載入 | 行內 `CircularProgressIndicator` | 「全部標為已讀」按鈕 |
| 提示 | `fluttertoast` | `MyToast.show()` |
| 提示 | `bot_toast` | 進度與遮罩 |

→ **方向**：收斂成一套。每一種狀態只能有一個長相，並且明確定義「整頁級」與
「區塊級」的分界。

**B2（P0）幾乎所有載入都是「一顆置中的轉圈」。**
使用者看不出接下來會出現什麼，也感受不到進度。課表、成績、資訊系統、課程檔案
都有穩定可預測的版面，全部適合骨架屏。

**B3（P0）錯誤訊息是工程語氣而且不分情境。**
`ErrorPage` 在「沒登入」「離線」「抓取失敗」三種情況下長得幾乎一樣，文案是
「發生錯誤」等級。使用者不知道該做什麼。
→ **方向**：每一種失敗原因要有自己的文案與自己的下一步動作。工程端已經把失敗
原因分成五種（見 §5.1），設計端只要各給一組文案 + 動作。

**B4（P1）`fluttertoast` 的顏色是寫死的白底黑字**（`lib/src/util/my_toast.dart`），
深色模式下會是一塊白色。而且重要結果用 toast 呈現——例如課表選單的「查詢學分」
按下去只跳一個一閃即逝的 toast 顯示總學分。

**B5（P1）全螢幕遮罩進度框太重。**
任何一次背景取資料都會蓋住整個畫面，使用者什麼都不能做。

### C. 逐畫面

**C1（P0）課表格子只顯示課名，字被壓到最小 10px。**
`AutoSizeText(minFontSize: 10, maxLines: 3)`。教室、時間、教師全部要點開對話框
才看得到——而「教室在哪」正是最高頻的需求（§1.2 情境 1）。格子高度是
「可用高度 ÷ 固定節數」硬算出來的（`CourseConfig.showCourseTableNum`）。

**C2（P0）課表沒有「現在」的概念。**
沒有標出今天是哪一欄、現在是第幾節、下一堂是哪一堂。

**C3（P1）課表的學期切換不像可點的控制項。**
學號（純文字、沒有標籤）+ 一顆 `TextButton` 顯示「114-1」加一個下箭頭，兩者並排
在課表上方一條 Row 裡。

**C4（P1）課表 AppBar 擠了三顆圖示，選單裡混了四件不同層級的事**：
查詢學分（跳 toast）、載入我的最愛、匯入自訂課程、設為 Android 桌面小工具。

**C5（P1）課程資訊對話框藏了兩個看不見的手勢**
（`course_table/modal/course_detail_dialog.dart`）：點課號 = 複製，長按課號 = 編輯
課號。編輯課號會直接寫進本機設定，而且是使用者救回「課程查詢 API 抓不到這門課」
的唯一手段——**這麼重要的功能沒有任何可見的入口**。

**C6（P0）資訊系統是 2 欄純文字方塊，每塊 120 高，沒有圖示、沒有分類色。**
六個分類（課務、個人資訊、校園生活、就學補助、活動、資源）只用一行小標題分隔。
純文字網格掃視效率很低。

**C7（P1）資訊系統頂端的 WebMail 那一列跟下方網格完全不同語彙。**
一個 50 高的 `GestureDetector` + `Row`，右邊有一顆「重新整理」圖示——但它實際的
功能是「重設 WebMail 密碼」。（工程端已補 tooltip 但圖示本身仍然誤導。）

**C8（P1）成績頁用可捲動的 TabBar 列學期。**
學期一多就要橫向捲才找得到。只有當學期的 GPA 與學分，沒有累計 GPA、沒有趨勢。
分數是右對齊純文字，不及格才變紅，點下去跳一個顯示同一個分數的 toast。

**C9（P1）行事曆的月曆佔掉上半螢幕，但學校行事曆事件只是純字串**，沒有時間、
沒有分類、不可點開。

**C10（P1）登入頁資訊不足。**
只有帳號、密碼兩個欄位加一行小字。沒有說明這是哪一組帳號、沒有顯示/隱藏密碼、
沒有區分「帳號錯」「密碼錯」「沒網路」。而且登入過程中可能突然彈出一個 WebView
（學校的 Turnstile 人機驗證），使用者完全沒有預期。

**C11（P2）設定頁的語言切換是一顆 Switch（中/英二元）**，切下去會 `Get.back()`
並把課表跳回第一頁，體感像 App 重啟。設定項目是 80 高的卡片，四項而已卻佔滿整頁。

**C12（P2）「其它」頁的個人資料載入失敗時，是一行灰字加一個小圖示**，看起來不像
可以點——但它其實是重試入口。

### D. 視覺系統

**D1（P0）沒有設計 token。**
- 顏色直接寫 `Get.theme.colorScheme.*`，沒有語意層（沒有「截止」「已繳交」
  「未通過」「未讀」的專屬色）。
- 字級直接寫 `fontSize:`，全 `lib/ui` 出現 36 次，值散落在 12/14/15/16/20/32。
- 圓角用了 8 / 10 / 12 / 14 / 999 五種。
- 垂直間距用了 2 / 4 / 6 / 8 / 10 / 12 / 14 / 16 / 20 / 24 / 28 / 32 / 48 / 120。

**D2（P1）進場動畫每次都跑，而且是 Scale + Fade 交錯。**
六個頁面用 `flutter_staggered_animations`，每次進頁、每次切回來都重跑一次。日常
高頻使用下會變成噪音。

**D3（P1）卡片語彙不一致。**
`SectionCard`（圓角 12、`surfaceContainer`、padding 14/12）是最新、最好的一套，
但只有公告與通知、作業詳情等新頁面在用。其他頁面各自寫自己的 `Container` +
`BoxDecoration`。

**D4（P2）圖示已統一為 Lucide**（自帶 `assets/fonts/lucide.ttf`，
`lib/ui/other/lucide_icons.dart`）。**這是好的基礎，維持它**——新設計要用的圖示
請優先從 Lucide 挑，用不到的字符工程端會再刪。

### E. 無障礙

**E1（P0）大量固定 `fontSize` 讓系統字級放大失效。**

**E2（P0）課表格子的字被 `AutoSizeText` 壓到 10px 以下。**

**E3（P1）課表格子與資訊系統方塊沒有 semantics label**，螢幕閱讀器只唸得到課名
或項目名，唸不到「星期三第 3 節，教室 TR-311」。

**E4（P1）課表格子的顏色是演算法生成的**（`UIUtils.generateHarmoniousColors`），
文字色靠 `UIUtils.getOnColor` 挑黑或白。對比度沒有被驗證過。

**E5（P2）純圖示按鈕大多已補 tooltip**——這是既有的好做法，新設計要延續。

## 5. 硬性限制（設計不可以違反）

### 5.1 每一個資料畫面都有四種樣貌，不是兩種

工程端的每一次取資料都回一個三態結果，加上「還在載入」共四種。**每一個顯示遠端
資料的畫面都必須畫這四種**：

| 狀態 | 意思 | 畫面要做什麼 |
|---|---|---|
| **載入中** | 還沒有結果 | 骨架屏（有穩定版面時）或進度指示 |
| **Ok** | 這次真的抓到新資料 | 正常內容 |
| **Stale** | 沒抓到，但本機快取讀得回來 | **正常內容 + 一條「你看到的是舊資料」橫幅**，橫幅要帶原因與重試入口 |
| **Failed** | 沒抓到也沒快取 | 錯誤畫面 + 針對原因的下一步動作 |

`Failed` 與 `Stale` 各有五種原因，**每一種的文案與動作都不同**：

| 原因 | 使用者該做什麼 | 可不可以重試 |
|---|---|---|
| 離線 | 檢查網路 | 可以 |
| 未登入 | **去登入**（畫登入按鈕，不要畫重試） | 不可以 |
| 登入失敗 | 重試（會靜默重新登入一次） | 可以 |
| 抓取失敗 | 重試 | 可以 |
| 這門課不支援 | 沒得救，說清楚為什麼 | 不可以 |

現況實作在 `lib/ui/components/page/result_view.dart`，Stale 橫幅已經有了但很陽春。

### 5.2 離線必須可用

課表、成績、課程檔案清單、行事曆都有本機快取。**斷網進 App 要看得到東西**，而且
要看得出來那是舊的。

### 5.3 兩種語言，字長差距很大

繁體中文與英文（`lib/l10n/intl_zh_TW.arb`、`intl_en.arb`，各 250 行）。
中文「同步臺科 Moodle 設定」對上英文 "Sync NTUST Moodle Settings"——**所有容器
都要能容納 1.6 倍的字長**。不要設計依賴固定字寬的版面。

### 5.4 沒有內建字體

字體是執行期從 Google Fonts 抓 Noto Sans TC（`google_fonts` 套件），**抓不到時會
退回系統字體**。所以：

- 可以指定字重與字級，**不要**指定第二種字族。
- 首次啟動或離線時使用者看到的是系統字體，設計不能依賴 Noto Sans TC 特有的字面
  比例。
- 需要等寬（例如成績、學分對齊）時請用「表格對齊」而不是等寬字體。

### 5.5 課表格子的顏色是演算法生成的

每門課的底色由 `UIUtils.generateHarmoniousColors` 依課程數量生成一組協調色，
不是設計端指定的。設計端可以**改變生成規則**（例如「從品牌色衍生的 8 色調色盤
循環取用」），但不能假設「每門課的顏色由我指定」。文字色必須在生成色上都通過
對比度檢查。

### 5.6 這些功能不能砍

每一個都有實際使用者：桌面小工具（Android）、我的最愛課表、自訂課程、匯入他人
課表、WebMail、Moodle 通知偏好設定、意見回饋、貢獻者名單、隱私權政策。

### 5.7 WebView 是逃不掉的

資訊系統的每一個項目、WebMail、部分 Moodle 連結、修改密碼、意見回饋都是把使用者
送進一個內嵌瀏覽器。設計端要處理的是**這個轉場的預期管理**：使用者要知道自己
即將離開 App 的原生介面、要知道大概要等多久、要能退回來。

### 5.8 不要引入新的 UI 套件

現有的 UI 相關相依已經偏多（`awesome_dialog`、`bot_toast`、`fluttertoast`、
`flutter_slidable`、`card_swiper`、`expansion_tile_card`、`flutter_staggered_animations`
⋯⋯）。這次翻新希望**減少**它們，不是增加。設計如果需要某個特殊互動，請先確認
用 Flutter 內建元件做得出來。

### 5.9 未讀紅點是 process 級狀態

Moodle 站內通知的未讀數會在 App 回到前景時刷新。設計要給它一個穩定的位置，並且
定義「0 未讀」時長什麼樣。

## 6. 交付物

### 6.1 設計 token（第一優先，其他東西都依賴它）

- **色彩**：TAT 品牌主色 + 完整的亮/暗兩套。要包含
  - 表面層級（背景、卡片、卡片上的卡片、分隔線）
  - 文字層級（主要、次要、停用）
  - 重音色與其上的文字色
  - **語意色**：成功 / 警告 / 錯誤 / 資訊 / 未讀 / 已逾期 / 進行中 / 已完成
  - 課表配色的生成規則（見 §5.5）
  - 每一組前景背景配對的對比度數值
- **字級**：一套完整的階梯（建議 7–9 級），每一級標明 size / weight / line-height /
  用途。**字級必須以相對方式定義**，讓系統字級放大能生效。
- **間距**：一套階梯（建議 4 的倍數，6 級以內）。
- **圓角**：最多 3 種 + 全圓。
- **陰影 / 分層**：最多 3 級。
- **動效**：時長與曲線各 2–3 種，並說明「什麼情況不要動畫」。

### 6.2 元件庫

必畫的：

| 元件 | 需要的變體 |
|---|---|
| 卡片 | 一般 / 可點 / 帶未讀標記 |
| 清單列 | 純文字 / 帶圖示 / 帶右側值 / 帶狀態標籤 / 可展開 |
| 分頁列（tab） | 2 項 / 4 項 / 6 項（超過要能捲）/ 帶數量標記 |
| 底部導航 | 未選 / 選中 / 帶紅點 |
| 頂部列 | 一般 / 帶動作 / 帶分頁列 / 帶搜尋 |
| 按鈕 | 主要 / 次要 / 文字 / 危險 / 圖示；一般 / 按下 / 停用 / 載入中 |
| 輸入欄 | 一般 / 聚焦 / 錯誤 / 停用 / 密碼（含顯示切換） |
| 狀態標籤（chip） | 至少涵蓋作業的：未繳交 / 已繳交 / 已逾期 / 已評分 |
| 空狀態 | 整頁級 / 區塊級 |
| 錯誤 | 整頁級 / 區塊級 / 對話框 |
| 骨架屏 | 課表 / 清單 / 卡片 / 個人資料 |
| 舊資料橫幅 | 五種原因各一 |
| 對話框 | 資訊 / 確認 / 危險確認 / 選擇清單 / 輸入 |
| 提示條（取代現在的 toast） | 一般 / 成功 / 錯誤 / 帶動作 |
| 進度 | 行內 / 頂部細條 / 全螢幕（如果保留的話） |
| 課表格子 | 一般 / 當前節次 / 已結束 / 自訂課程 / 空堂 |
| 檔案列 | 各檔案類型圖示（工程端已有 29 個單色 SVG） |

### 6.3 畫面 artboard

**每個資料畫面要畫四張**（載入中 / Ok / Stale / Failed）。其他畫面畫一張。

優先順序：

- **第一批（必須）**：今日或首頁（若採用）、課表、課程頁（合併後）、公告與通知、
  成績、行事曆、資訊系統、我的課程清單（若採用）
- **第二批**：登入、其它/個人、設定、作業詳情、課程檔案、課程公告
- **第三批**：關於、貢獻者、自訂課程、WebView 外框、啟動公告、更新提示

亮色與暗色都要。至少一組要用最長的中文字串與最長的英文字串各驗一次。

### 6.4 流程圖

- **首次啟動 → 隱私權同意 → 登入 →（可能的 Turnstile WebView）→ 主畫面**：
  每一步的預期管理與失敗處理。
- **從「開 App」到「知道下一堂課在哪 / 有什麼作業快到期」**：目標是兩步以內。

### 6.5 規格標註

工程端是 Flutter，要能直接對照著寫。每個元件請標：尺寸、間距、字級 token 名、
顏色 token 名、狀態變化、以及**這一顆是不是依平台切換外觀**（§2.1）。

## 7. 驗收標準

一份可以交付的設計要能回答以下每一題：

1. 使用者開 App 的第一眼，能不能回答「下一堂課在哪」與「什麼快到期」？
2. 每一個顯示遠端資料的畫面，四種狀態是不是都畫了？
3. 五種失敗原因是不是各有自己的文案與下一步動作？
4. 「舊資料」的樣貌是不是一眼認得出來，而且不會擋住內容？
5. 錯誤畫面剩幾套？載入畫面剩幾套？提示剩幾套？（答案應該各是一套）
6. 進入任何一門課的內容，最少要幾步？課表載入失敗時還進得去嗎？
7. 「課程資料」與「課程詳情」還是兩個入口嗎？
8. 所有前景/背景配對的對比度是多少？課表格子的生成色也算。
9. 系統字級放到最大時，課表格子、成績列、分頁列會怎樣？
10. 最長的中文字串與最長的英文字串放進去會不會爆版？
11. 深色模式下有沒有任何一塊是亮的？（現在的 toast 就是）
12. 這份設計放在 iPhone 上會不會像一個 Android App？放在 Android 上會不會像一個
    移植過來的 iOS App？（兩題的答案都要是「不會」）

## 9. 需要設計端回答的開放問題

這幾題沒有既定答案，設計提案時請一併說明選擇與理由：

1. 「今日」該是一個新分頁、課表頁的上半、還是取代課表成為預設分頁？
2. 底部導航最終是幾項？「資訊系統」與「其它」要不要合併成「更多」？
3. 合併後的「課程」頁有最多 6 個分頁，分頁列要怎麼處理？（可捲動 tab / 分段控制 /
   改成單頁捲動 + 錨點 / 首頁式的區塊）
4. 課表要不要保留「一次看整週」的格線？還是改成「日 + 週」兩種視角？
   （格線是很多使用者的既有心智模型，改動要有理由。）
5. 全螢幕進度遮罩要保留嗎？如果不保留，長時間的請求要怎麼表達？
6. 課表配色的生成規則要怎麼從品牌色衍生，而且保證對比度？
